# Streaming audit — SSE across Go, Node, and Python

Streams 1,10, 100 events each, 5 streams per connection, 2 repetitions.
Best and median of the repetitions are both reported, with the spread.

Every server does the same work: the same number of streams, each carrying
the same number of events. Throughput is derived from the time that work
actually took, so a faster server is not penalised for finishing early.

Every server emits byte-identical frames; that is verified before every
run by equivcheck, and a mismatch fails the run rather than being reported.

**Read the language column before comparing rows.** Go, Node, and Python
differ by more than the frameworks do: CPython's GIL, libuv's event loop, and
Go's goroutines are the dominant variable. The honest reading is "photon
against the best of each ecosystem", not "faster than FastAPI".

Each language's floor (net/http, node:http, raw ASGI) is in the table on
purpose: without it, the comparison is between whole stacks rather than
between frameworks.

TTFE is the median time to first event, which is what a user perceives as
responsiveness. RSS is the server process's own peak, read in-process.
Each server runs alone; the driver is a separate process, so no client cost
is inside a server's measurement.
